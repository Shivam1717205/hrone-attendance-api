# Review of the starter

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` | It treats a punch as late only after the integer-minute difference exceeds 10, rather than after elapsed time is strictly greater than 10 minutes. It also anchors the shift to the punch's calendar date, which is wrong for overnight shifts. | For a 09:30 shift, 09:40:01 must be 10 late minutes; an overnight employee's early-morning punch belongs to the prior shift date. | Compare elapsed seconds to 600 and floor the elapsed minutes; anchor shift start to the attendance date. |
| 2 | `compute_work_hours` | Built-in `round` uses ties-to-even and the input may still include fractional seconds. | Construct a duration exactly halfway between hundredths of an hour, or submit a timestamp ending in fractional seconds. | Truncate instants to seconds and use decimal half-up quantization. |
| 3 | `compute_overtime` | It puts shift end on the same date for overnight shifts, mixes naive and aware datetimes, and counts any positive overtime rather than requiring 30 minutes. | A 22:00-06:00 shift ending at 06:29 should have zero overtime; 06:30 should have 30. | Build the shift-end instant from the attendance date (next day for overnight shifts), use UTC-aware instants, and apply the 30-minute threshold. |
| 4 | `health` | It returns success without checking MongoDB. | Stop MongoDB and call `/health`; the starter still returns 200. | Ping MongoDB and return 503 on a PyMongo connectivity error. |
| 5 | `EmployeeIn` | It accepts malformed employee codes, emails, shift times and dates, and permits identical shift start/end values. | Submit an invalid `emp_code`, `joined_on`, `shift_start`, or equal shifts; these should be rejected with 422. | Add schema-aligned field constraints, date parsing, and a distinct-shift check. |
| 6 | `create_employee` / startup | A read-before-insert duplicate check is racy, and there is no unique index to protect the invariant or create indexes at startup. | Send concurrent employee creates with the same code; more than one can pass the check without a unique index. | Create idempotent indexes at startup and map duplicate-key errors to 409. |
| 7 | `create_employee` / employee responses | `created_at` is naive and is returned as a datetime string, not epoch milliseconds. | Inspect the created employee JSON; the contract requires an integer timestamp. | Store UTC-aware timestamps and serialize instants to epoch milliseconds. |
| 8 | `list_employees` | The skip is `page * page_size`, the total ignores the department filter, and results are not sorted or bounded by the contract. | Page 1 skips its first page; a department query reports the whole collection total. | Use `(page - 1) * page_size`, filtered counts, ascending code sort, and page-size constraints. |
| 9 | `punch_in` | Unknown employee codes are dereferenced and can cause a 500. | Punch in using an employee code not in `employees`. | Return 404 before using employee shift data. |
| 10 | `punch_in` / `PunchInIn` | Timestamp coercion and host-local conversion can accept invalid instants or produce a wrong date; IST, overnight attendance-date assignment, and whole-second truncation are missing. Status is not restricted to presence statuses. | Send seconds, a float, a string, or a punch near the IST/overnight boundary. | Enforce strict bounded integer milliseconds, convert from UTC, apply R1, and constrain status values. |
| 11 | `punch_in` | Duplicate prevention is another check-then-insert race. | Send simultaneous punch-ins for one employee and attendance date. | Rely on a unique `(emp_code, date)` index and translate its duplicate-key error to 409. |
| 12 | `punch_in` / response shape | It returns an `id` based on MongoDB `_id`, although attendance records have no API id. Stored datetimes also need conversion at the API boundary. | Compare the JSON response to the `AttendanceRecord` contract. | Omit `_id`/`id` and serialize all instant values as epoch milliseconds. |
| 13 | `list_attendance` | It reads and sorts every matching document in Python, which does not scale to 100k records; its sort omits the employee-code tie-break, and pagination bounds/date-order validation are missing. | Exercise it with a large date range, tied dates, invalid ranges, or oversized page size. | Count filtered records separately and use a sorted, paginated MongoDB cursor with validated filters and indexes. |
| 14 | `list_attendance` / startup | Legacy missing fields are not normalized in responses, and the natural key and list-query indexes are absent. | Seed records without `history` or `half_day`, and inspect query plans. | Fill required response defaults and create the compound indexes during startup. |
| 15 | Missing routes | The starter omits punch-out, regularization, all four analytics routes, and the explain route. | Request any of those documented paths. | Implement the remaining routes, using MongoDB aggregations for analytics and explain plans. |
| 16 | `ensure_month` | The `YYYY-MM` pattern accepted year `0000`, but constructing a Python `date` for it raised an uncaught `ValueError`. | Request a monthly analytics or explain query with `month=0000-01`; it failed as a server error instead of validation. | Reject year zero with HTTP 422 before constructing the month dates. |

### Looked at and not a defect

- `list_attendance` already used the correct one-based page offset expression `(page - 1) * page_size`; the employee list did not.
- ISO `YYYY-MM-DD` strings can be compared lexically for inclusive date filters because the format is fixed-width and ordered.
- The default punch-in status is `PRESENT`, and `sample_seed.py` reads both MongoDB settings from the environment after loading `.env`; those behaviors match the contract.

### Monthly employee analytics verification

- Reviewed `employee_monthly_pipeline` and its endpoint against the monthly analytics contract and R5-R8. The inclusive match uses the requested month’s `YYYY-MM-DD` bounds; `$dateFromString` parses those stored strings, and MongoDB `$dayOfWeek` values 2-6 correctly select Monday-Friday. Presence is restricted to `PRESENT`, `WFH`, and `ON_DUTY`; half days count as 0.5; `LEAVE` is counted separately; and missing documents do not become synthetic absences. Late and overtime totals use the stored values across all matching dates, including weekends. The endpoint calculates working days from `joined_on` and rounds attendance rates to four decimal places half-up.
- The reported October 2026 example has a `PRESENT` record on Saturday, October 10, with 380 late minutes. Under R7, that record contributes to `late_count` and `total_late_minutes`, but not `present_days`. If it is the only matching record, `present_days: 0` and `attendance_pct: 0` are expected; no monthly aggregation defect was confirmed, so production aggregation logic was not changed.
- Added isolated MongoDB aggregation tests for weekday full/half-day presence, Saturday presence, `LEAVE`, `ABSENT`, missing records, month boundaries, late/overtime totals, and attendance-rate rounding. The tests create and drop a uniquely named temporary database and do not use the seeded application database.
- The monthly endpoint initially generated a generic response schema rather than the `EmployeeMonthly` schema declared by `openapi.yaml`. Added an explicit response model and a generated-OpenAPI contract test; the analytics calculation and response fields are unchanged.
